# 数据协议

## 坐标与时间

雷达坐标以 `y` 为前向距离、`x` 为横向距离，单位为米；方位角按 `atan2(x, y)` 计算。ROS 里程计使用 `twist.twist.linear.x` 和 `twist.twist.angular.z`，分别表示前向速度（m/s）与角速度（rad/s）。

实时雷达帧的 `sample_time_sec` 为完整帧接收时刻估计，`time_quality=receive_estimate`。`last_measurement_time_sec` 仅随接受的目标测量更新，预测和待确认帧不刷新。

## 里程计共享内存

默认 key 为 `123458`，可通过 `RADAR_ODOM_SHM_KEY` 配置。C++ 读端与 ROS 接收器须使用相同 key。ODM8 数据包长 32 字节，Python 布局为 `=dffIIII`。

| 字节偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | float64 | 回调接收时间，Unix 秒 |
| 8 | float32 | 前向速度，m/s |
| 12 | float32 | 角速度，rad/s |
| 16 | uint32 | 写入序号 |
| 20 | uint32 | FNV-1a 校验值 |
| 24 | uint32 | 协议标记 `0x384D444F` |
| 28 | uint32 | 写入进程标识 |

校验覆盖字节 `0–19` 和 `24–31`。时间戳无效、超前超过 0.05 秒、年龄超过 0.5 秒或校验失败时，数据不能用于有效里程计补偿。ROS 消息头年龄单独用于诊断。

## 21 列跟踪记录

跟踪文件位于 `track_txt/`，字段以空白分隔，时间戳为单个 ISO 格式字段。

| 列号 | 字段 |
| --- | --- |
| 1 | target_id，目标显示编号 |
| 2–5 | 滤波后的 x、y、距离、方位角 |
| 6–9 | 实测 x、y、距离、方位角；无实测时为 nan |
| 10 | has_measurement，0 或 1 |
| 11 | confidence |
| 12 | frame |
| 13 | lost_frames |
| 14 | stable_frames |
| 15 | 输出时间戳 |
| 16 | realtime 或 offline |
| 17 | TRACKING、PREDICTED 或 STOPPED |
| 18 | speed_scale，0–1 |
| 19 | allow_translation，0 或 1 |
| 20 | allow_yaw，0 或 1 |
| 21 | reacquire_hits |

`TRACKING` 要求当前测量有效且 `lost_frames=0`。`STOPPED` 要求速度比例及运动许可均为零。桥接结合状态、比例、许可字段和数据有效期发布速度，离线记录不作为实时控制输入。重复帧不会被视为新观测。

## 控制元数据

同名 `.txt.meta.json` 文件使用 `schema_version=1`，包含帧号、目标号、会话、选择序号、UID、接收时间、估计采样时间、最近接受测量时间、预测标志、位置方差、运动原因和 `force_stop` 等字段。64 位标识以十进制字符串保存。

元数据以原子方式提交，内含 `record_line`，用于读取一致的 21 列控制快照。帧或目标不匹配、会话不匹配、数据过期、元数据损坏或显式停止时输出零速度。无当前测量的运动预测另受 0.35 秒最近实测年龄限制。启用视觉保护时，`vision_guard` 中的许可、证据时效和选择会话也必须有效。

## 录制文件

雷达 BIN 仅保存完整 ADC 帧。配套 `.bin.frames.csv` 包含 `source_frame,session_id,received_time_sec,sample_time_sec,time_quality`；每个保存帧对应一行，源帧号允许有间隔。无索引的 BIN 按连续物理帧读取。

`txt/` 保存点云，`track_txt/` 和 `track_csv/` 保存目标轨迹，`tracking_diagnostics/` 保存处理与跟踪诊断。相机记录位于 `camera_recordings/`，其中 `camera.mjpg` 保存图像，`frames.jsonl` 保存偏移、长度、时间和人物框，`events.jsonl` 保存会话及雷达控制事件，`summary.json` 保存录制统计。
