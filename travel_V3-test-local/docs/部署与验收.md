# 部署与验收

## 本地检查

运行 `bash scripts/build/build.sh cpu` 和 `bash scripts/build/build.sh wsl`。CPU 配置无需 Qt、CUDA 或 ROS；WSL GUI 使用 Qt/OpenCV 与 CPU FFT。

无显示服务时可使用 QT_QPA_PLATFORM=offscreen 运行 GUI 测试。cooperative_layout_test 的 --screenshot 参数可导出人工数据预览，覆盖布局与生命周期，不能作为设备闭环证据。

## Jetson 与 ROS

1. 准备 ROS 2 Humble、底盘驱动、Qt、OpenCV DNN 和 CUDA/cuFFT，另行放置 YOLO11 ONNX 模型。
2. 将本地设置及录制成套迁移；模型使用显式路径。核对原 gui_runtime.ini 的设备路径和速度值。
3. 在当前工程运行 scripts/build/build_ros2.sh，以 --symlink-install 构建当前包；运行 scripts/build/build.sh jetson。
4. RADAR_ROS_SETUP 指定 ROS 环境，默认 /opt/ros/humble/setup.bash。底盘环境通过 GUI 或 WHEELTEC_SETUP 指定。
5. scripts/run/run_gui.sh 启动 GUI。helper 会先运行 scripts/runtime/verify_ros_overlay.py，校验 Python 源码、版本和 ROS share 目录。

移动项目后重新构建 ROS overlay。包名仍为 my_radar_follower，bridge.yaml 由 ROS 包拥有并安装，主配置目录不复制控制 YAML。CUDA 架构沿用原默认值 87，其他设备通过 -DCMAKE_CUDA_ARCHITECTURES 明确指定。

可选独立入口为 scripts/run/run_sensing.sh 与 scripts/run/run_follow.sh。它们沿用原行为：底盘驱动由外部管理，sensing 接收里程计，follow 启动随行控制。不要与 GUI 管理的同话题会话同时运行。

## 实机检查清单

- 执行 Jetson CTest，确认 CUDA FFT contract 实际运行；跳过不能记录为硬件通过。
- 相机 probe 使用真实设备和模型，至少获取五帧；前后比对录制目录，确认没有新增图像或会话。生产录制默认行为不变。
- 雷达预选、确认锁定、人工视觉关联成立，相机选人不会启动底盘。
- 核对视觉保护默认关闭，启用后验证人物丢失、歧义及过期证据的许可处理。
- 验证停止追踪、停止采集、相机回放、GUI 退出和 helper 异常时的停车、lease 撤销及所属进程清理。
- 使用自定义 RADAR_DATA_ROOT、RADAR_TRACK_DIR 检查 GUI、bridge、odom 和 runtime 路径一致，目录归属校验有效。
- 换 cwd、移动项目后确认资源定位正确；其他工程 overlay 仍被拒绝。
- 检查 BIN/索引、TXT/metadata、相机会话完整性及新配置不覆盖旧参数。

当前实施主机没有 ROS Humble、nvcc 或实际传感器/底盘；上述项目须在部署设备完成。Python mock、IPC 和 offscreen 测试只证明相应软件行为。

## 回退

停止应用并保存 var/ 和外部数据。在项目旁克隆本地 Git 仓库，检出 baseline-before-cleanup，恢复原结构；将所需配置和录制复制到该快照要求的位置，再全新编译。旧构建目录不作为回退依赖。

若只回退某个阶段，使用 Git 提交历史选择版本，并按该版本 README 重新构建。不要在有未提交修改的活动目录直接覆盖源码或数据。
